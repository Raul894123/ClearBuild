# ClearBuild · SAQ QURYLYS — бэкенд

> ⚠️ **Демонстрационные данные.** Все ЖК, застройщики, БИН, телефоны и объявления в `seed.json` и `samples/`
> вымышлены (помечены «-Демо»). Система выявляет **индикаторы риска** и не утверждает факт нарушения:
> решение всегда принимает аналитик.

FastAPI + SQLAlchemy + SQLite. Сверяет ЖК с госреестрами и рекламой, считает детерминированный
скоринг R1–R6 и цветовую зону. Фронтенд (корень репозитория) обращается к `/api/v1`, а если бэкенд
недоступен, работает на локальных данных.

**Онлайн-версия (Swagger):** https://clearbuild-sooq.onrender.com/docs
(бесплатный тариф Render засыпает без запросов, поэтому первый ответ может идти около минуты).

## Установка и запуск

Нужен Python 3.11+ (проверено на 3.13 и 3.14). Все команды ниже выполняются **из папки `backend/`**:
`main.py` импортирует пакет `app`, поэтому из корня репозитория uvicorn его не найдёт.

### Windows

```bat
cd backend
run_backend.bat
```

Скрипт сам создаёт `.venv` и ставит зависимости из `requirements.txt`, если их нет, затем запускает
сервер на http://localhost:8000. Другой порт: `run_backend.bat 8001` или `PORT` в `.env`.

Вручную (PowerShell или cmd):

```bat
cd backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
```

### Linux / macOS

```bash
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --reload --port 8000
```

### Проверка

- http://localhost:8000/docs — Swagger (на него же редиректят `/`, `/api`, `/api/v1`);
- http://localhost:8000/api/v1/health — `{"status": "healthy", "DEMO_MODE": true, "complexes_count": 8, ...}`.

При первом запуске создаётся `backend/clearbuild_demo.db` и заполняется из `seed.json` (9 ЖК). Если база уже есть, при старте в неё докидываются ЖК из сида, которых там ещё нет (вместе с их объявлениями).
Чтобы сбросить демо-данные, остановите сервер и удалите этот файл. После изменения схемы БД файл
тоже нужно удалить: миграций нет, и сервер со старой БД остановится с понятной ошибкой.

### Переменные окружения

Все необязательны, см. [`.env.example`](.env.example). Скопируйте его в `.env`: `run_*.bat` прочитают
его сами, в Linux — `set -a; . ./.env; set +a`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BACKEND_DB_URL` | `sqlite:///backend/clearbuild_demo.db` | URL базы SQLAlchemy |
| `PORT` | `8000` | порт для `run_backend.bat` |

Секретов и ключей бэкенд не использует.

## Эндпоинты

Все пути доступны под `/api/v1/...` (основной, его использует фронтенд) и `/api/...` (алиасы по ТЗ1,
в Swagger не показаны). Перечисления принимаются в любом регистре, неверное значение даёт 422.

| Метод и путь | Назначение |
|---|---|
| `GET /health` | статус сервера, число ЖК и публикаций |
| `GET /complexes?zone=red\|yellow\|green\|all` | список ЖК со скорингом (`riskProfile`) и сверкой по реестрам (`govChecks`) |
| `GET /complexes/{id}` | карточка ЖК: расшифровка R1–R6, `govChecks`, публикации, текущая сигнальная карточка |
| `POST /complexes` | добавить ЖК |
| `DELETE /complexes/{id}` | полное удаление ЖК из SQLite и каскадное удаление сигналов, публикаций и аудита |
| `GET /geocode` | геокодирование адреса г. Усть-Каменогорска и привязка к координатам OSM |
| `POST /complexes/purge-tests` | очистка временных/тестовых демонстрационных ЖК |
| `POST /complexes/{id}/confirm-factor` | решение аналитика по фактору: `CONFIRMED` / `REJECTED` / `NONE` / `AUTO` (сброс) |
| `POST /complexes/{id}/signal-decision` | утвердить / вернуть / отклонить сигнальную карточку |
| `POST /signals/{id}/decision` | то же, путь по ТЗ1 |
| `GET /publications` | рекламные объявления |
| `POST /publications` | добавить объявление (сразу анализируется, статус «на проверке») |
| `POST /publications/{id}/verify` | `accept` / `reject` гипотезы ИИ, затем пересчёт скоринга и запись в аудит |
| `POST /analyze` | анализ текста объявления: гипотезы R2, R3, R5 с триггерами и уверенностью (в балл не идут) |
| `POST /registries/import` | импорт выгрузки разрешений МИО Ashyq Data (CSV или JSON), примеры в `samples/` |
| `GET /audit-log?limit=100` | журнал действий аналитиков (новые сверху) |

### Импорт Ashyq Data

Строки сопоставляются с ЖК сначала по БИН, затем по названию. При конфликте или неоднозначности
строка пропускается с причиной. Найденный ЖК получает правовое основание из выгрузки, ненайденный
создаётся со статусом «Нужна проверка». Импорт **никогда не подтверждает R1**: отозванное или
аннулированное разрешение ставит «Нужна проверка» (`unknown`, 0 баллов), а отсутствие основания
подтверждает только аналитик через `confirm-factor`. Уже подтверждённое отсутствие основания импорт
не откатывает.

## Скоринг R1–R6

| Фактор | Баллы | Когда засчитывается |
|---|---|---|
| R1 — нет правового основания | 35 | только `legal_basis_type = absent` (нет гарантии КЖК и разрешения МИО). `unknown` = «Нужна проверка», 0 баллов |
| R2 — прямая оплата застройщику | 25 | подтверждённая аналитиком публикация с предложением прямой оплаты (без ДДУ/КЖК) |
| R3 — продажа до ввода | 10 | подтверждённая активная реклама продаж; к введённому в эксплуатацию ЖК не применяется |
| R4 — коллективная жалоба | 15 | есть коллективная жалоба дольщиков |
| R5 — завышенная готовность | 10 | заявленная готовность выше проверенной на 20 п.п. и больше (обе даты и оба источника известны) |
| R6 — значительная задержка | 5 | есть существенная задержка сроков |

- `score = min(100, сумма баллов CONFIRMED-факторов)`.
- **Human-in-the-loop:** считаются только `CONFIRMED`. Гипотезы ИИ (`AI_HYPOTHESIS`), «Нужна проверка»
  (`UNVERIFIED`) и `NONE` дают 0. ИИ сам баллы не добавляет: объявление «на проверке» показывается
  как гипотеза.
- Аналитик не может обойти жёсткие правила: подтвердить R3 для введённого ЖК или R5 при разрыве
  меньше 20 п.п. нельзя (400). Подтверждение R1 переводит ЖК в `absent`.

### Зоны

| Зона | Условие |
|---|---|
| 🔴 Красная | `score ≥ 60` **и** подтверждены R1 и R2 |
| 🟡 Жёлтая | `score ≥ 25` в остальных случаях (в том числе ≥ 60 без пары R1+R2) |
| 🟢 Зелёная | `score < 25` |

## Контрольные кейсы

Проверяются тестами (`test_scoring.py`, `SEED_EXPECTED` в `test_api.py`).

| Кейс | ЖК | Подтверждённые факторы | Балл | Зона |
|---|---|---|---|---|
| **A** | jk-2 «Сатпаев Сити Парк» | R2 + R3; R1 «Нужна проверка» (0) | 35 | 🟡 Жёлтая |
| **B** | jk-1 «Ертіс Рівер Тауэрс» | R1 + R2 + R3; R5 пока гипотеза ИИ (0) | 70 | 🔴 Красная |
| **C** | jk-3 «Алтай Премиум Резиденс» | R3; гарантия КЖК есть | 10 | 🟢 Зелёная |

Кейс A показывает, что «нет данных» не равно «нарушение». Кейс B — полный набор для красной зоны.
Кейс C — легальный объект, у которого есть только реклама.

Остальные ЖК сида: jk-4 = 100 🔴, jk-5 = 60 🟡 (балл ≥ 60, но R2 ещё гипотеза ИИ, поэтому не красная),
jk-6 = 5 🟢, jk-7 = 10 🟢, jk-8 = 0 🟢, jk-9 «New Life» = 30 🟡 (R3+R4+R6, R1 «Нужна проверка»).

## Структура

```
backend/
├── app/
│   ├── main.py        эндпоинты (один APIRouter под /api/v1 и /api)
│   ├── factors.py     вывод R1–R6 из данных БД и решений аналитика
│   ├── scoring.py     веса, сумма баллов, зоны
│   ├── analyzer.py    rule-based анализ объявлений (гипотезы R2/R3/R5)
│   ├── registries.py  11 госреестров (govChecks), разбор выгрузки Ashyq Data
│   ├── mappers.py     БД → формат API (camelCase, ISO 8601 +05:00)
│   ├── models.py      таблицы Complex, Publication, Signal, AuditLog
│   ├── schemas.py     модели запросов
│   ├── seed.py        создание таблиц и загрузка seed.json
│   └── db.py          подключение к БД
├── samples/           примеры выгрузки Ashyq Data (CSV, JSON)
├── tests/
├── seed.json          демонстрационные данные (9 ЖК)
├── DATA_DIFF.md       расхождения с js/data.js фронтенда
├── run_backend.bat
├── run_tests.bat
└── .env.example
```
